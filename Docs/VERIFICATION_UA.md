# Перевірка стартового проєкту

Дата перевірки: 3 жовтня 2026 року.

## Виконано

Шість збірок скомпільовано окремо зі строгими попередженнями, без будь-яких Unity DLL:
`Synaps.Core`, `Synaps.Search`, `Synaps.AI`, `Synaps.Input`, `Synaps.KnowledgeGraph`, `Synaps.Data`.

Запущено ті самі 21 поведінкові тести, що знаходяться в `CoreBehaviorTests.cs`, через standalone runner:
**21 passed, 0 failed**.

Перевірені сценарії:

- Повторне Save не дублює й не пересуває вузол; зовнішня зміна snapshot не змінює граф.
- Спрямовані типізовані зв’язки дедуплікуються; відсутні кінці та self-edge відхиляються.
- Видалення вузла прибирає вхідні й вихідні зв’язки; список сусідів не має дублікатів.
- Некоректні координати, типи вузлів, дубльовані ID та dangling edges відхиляються.
- Після помилки Save граф залишається dirty; після невдалого Load попередній in-memory стан зберігається.
- Workspace-вибір, режим Connect і переміщення працюють через спільний `IWorkspaceInteraction`.
- Файловий репозиторій повторно читає вузли, зв’язки, Unicode, summary та позиції через інжектований test-codec.
- Пошкоджений основний файл відновлюється з backup; backup зберігається, пошкоджений оригінал архівується.
- Невалідний документ не підміняється порожнім; майбутня версія схеми не замінюється старою backup-версією.
- Невалідний результат серіалізації не замінює попередній файл і не залишає тимчасових файлів.
- Застарілі відповіді й помилки search-provider не перезаписують новий пошук, навіть без кооперативного cancellation.
- Порожній запит, скасування, помилка провайдера, повторний успішний пошук і Dispose мають очікувані стани.
- View не може змінити власний стан SearchController через отриманий DTO.

Додатково перевірено конфігурацію проєкту: JSON-файли, посилання між `.asmdef`, відсутність циклів,
`noEngineReferences` для доменних модулів, GUID та посилання bootstrap у сцені/build settings.

## Межі перевірки

Unity Editor недоступний у цьому середовищі. Імпорт пакетів, компіляцію Unity-адаптерів,
відкриття YAML-сцени, Play Mode та візуальне відображення не запускали.

Standalone-файлові тести використовують XML test-codec через `IGraphSerializer`, щоб перевіряти реальний
`FileGraphRepository` без Unity. Вони **не підтверджують** поведінку Unity `JsonUtility`.
Для цього додані ще три EditMode-тести в `UnityJsonGraphSerializerTests.cs`:
JSON round-trip, відхилення неповного документа та збереження/повторне відкриття JSON-файла.
Разом у Unity Test Runner має бути 24 тести.

## Перша перевірка в Unity

1. Дочекатися імпорту пакетів і переконатися, що Console не має compile errors.
2. Запустити всі 24 EditMode-тести.
3. Відкрити `DesktopPrototype.unity`, натиснути Play і Search; перевірити п’ять карток.
4. Ввести новий запит і натиснути Enter; клік поза полем не має запускати додатковий пошук.
5. Створити два вузли, отримати Summary, перетягнути вузол і з’єднати їх через Connect.
6. Натиснути Save graph, перезапустити Play і перевірити позиції, summary та зв’язок.
7. Видалити один вузол; його зв’язки мають зникнути та лишитися видаленими після перезапуску.
8. Перевірити розміри Game view; камера автоматично вміщує workspace.

У разі помилки імпорту або Play Mode збережи текст помилки з Unity Console.
Для Quest надалі потрібні окремі перевірки XR-вводу, performance, IL2CPP та файлового адаптера на пристрої.
